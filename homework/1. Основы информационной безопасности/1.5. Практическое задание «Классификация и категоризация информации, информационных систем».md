# Ответ
## Задание 1
###  1. Количество ИСПДн

**Выявлено:** `2` ИСПДн.  
**Обоснование:**  
Подразделения группируются в ИСПДн по фактическому процессу обработки ПДн, а не по организационной структуре. Бухгалтерия и отдел кадров обрабатывают одинаковый состав ПДн об одних и тех же субъектах (сотрудники компании) в одном и том же ПО «Зарплата и кадры» — по совокупности признаков (состав данных, субъекты, ПО) это одна информационная система, используемая двумя подразделениями.  
Клиентская служба обрабатывает иной состав ПДн о других субъектах (клиенты) в отдельном ПО «Счастливый клиент», поэтому образует самостоятельную ИСПДн.  
  
**Подразделения, не вошедшие в перечень ИСПДн:**
Постирочный цех и гладильный цех. По опросным листам дан чёткий отрицательный ответ: данные физических лиц в них не обрабатываются (сотрудники цехов выполняют производственные операции с изделиями, данные заказчиков в цеха не поступают).  
В соответствии с примечанием к опросному листу дальнейшее заполнение не требуется.  

### 2. Список выявленных ИСПДн
- **ИСПДн 1:** Кадрово-бухгалтерская ИСПДн (бухгалтерия + отдел кадров), к ней относится ПО «`Зарплата и кадры`»;  
- **ИСПДн 2:** ИСПДн клиентской службы (база клиентов), к ней относится ПО «`Счастливый клиент`».  

### 3. Критерии определения уровня защищённости
Перечислите критерии из ПП № 1119, которые используются в вашем решении:  
- **Критерий 1: категория обрабатываемых ПДн** — специальные / биометрические / общедоступные / иные (п. 5 ПП № 1119);  
- **Критерий 2: категория субъектов ПДн** — сотрудники оператора либо субъекты, не являющиеся сотрудниками (п. 5 ПП № 1119);  
- **Критерий 3: количество субъектов, чьи ПДн обрабатываются** — менее либо более 100 000 (пп. 9–12 ПП № 1119);  
- **Критерий 4: тип актуальных угроз** — 1-й (связаны с наличием недокументированных (недекларированных) возможностей в системном ПО), 2-й (в прикладном ПО), 3-й (не связанные с НДВ в ПО) (п. 6 ПП № 1119).  
  
По совокупности критериев устанавливается один из четырёх уровней защищённости: УЗ-1 (наивысший) — УЗ-4 (низший) (п. 8 ПП № 1119).

| Идентификация и аутентификация субъектов доступа и объектов доступа (ИАФ) | Индивидуальные учётные записи операторов клиентской службы, парольная защита | Каждый оператор работает в «Счастливый клиент» под собственной учётной записью со сложным паролем; вход — только со своего АРМ |
| Управление доступом субъектов доступа к объектам доступа (УПД) | Разграничение доступа к записям клиентов, ограничение неуспешных попыток входа, запрет массовой выгрузки ПДн | Оператор видит только свой участок базы; после нескольких неуспешных попыток входа учётная запись блокируется; выгрузка базы доступна только руководителю клиентской службы |
| Регистрация событий безопасности (РСБ) | Регистрация действий с базой клиентов, защита журнала событий | Журналируются входы, изменения и выгрузки данных; доступ к содержанию электронного журнала — только у должностных лиц, которым он необходим по служебным обязанностям (требование п. 15 ПП № 1119 для УЗ-2) |
| Антивирусная защита (АВЗ) | Антивирусное средство на АРМ и сервере клиентской службы, обновление баз | Антивирус с автоматическим обновлением баз; для УЗ-2 применяемые СЗИ — не ниже 5 класса и 5 уровня доверия (п. 12 приказа № 21) |
| Ограничение программной среды (ОПС) | Перечень разрешённого ПО на АРМ клиентской службы | На АРМ — только ОС, «Счастливый клиент», офисный пакет и антивирус; установка ПО выполняется только ИТ-специалистом |
| Обнаружение вторжений (СОВ) | Средства обнаружения вторжений на сервере с клиентской базой | Контроль подозрительной активности и попыток несанкционированного доступа к базе (группа СОВ полностью входит в базовый набор с УЗ-2) |
| Дополнительные меры при угрозах 1-го и 2-го типов (п. 11 приказа № 21) | Проверка ПО «Счастливый клиент» на отсутствие недекларированных (недокументированных) возможностей, тестирование системы на проникновение | Заказывается аудит (анализ кода) системы у стороннего специалиста; фрилансеру ставится требование доработки с применением методов защищённого программирования; при невозможности обеспечить — поэтапная замена на типовое сертифицированное решение |
| Обеспечение доступности персональных данных (ОДТ) | Резервное копирование базы клиентов | Ежедневное автоматическое резервное копирование БД на отдельный носитель, хранящийся в сейфе; периодическая проверка восстановления из копий |
  
*Базовый набор мер для УЗ-2 — 66 мер (п. 9 приказа № 21); состав формируется по схеме: базовый набор → адаптация → уточнение под актуальные угрозы → дополнение из иных НПА. Поскольку актуальны угрозы 2-го типа, дополнительно применяются меры п. 11 приказа № 21 (проверка ПО на НДВ, тестирование на проникновение).*
